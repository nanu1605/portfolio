# Cross-device UX and motion

**Status:** binding for Phases 2–7. Added 20 Oct 2026 after Tanishq asked for the best UI/UX, with animation, on phones, tablets and PCs.

The spec mostly describes desktop and limits several effects to fine pointers. This document gives every effect and layout a phone, tablet and desktop version. Touch devices get touch-native animation instead of nothing.

It comes from a four-part audit of the spec (motion, layout, device performance, testing) plus a critic pass. Where this document changes the spec, the change is listed in §9 and recorded in `docs/decisions.md`.

## 1. Device classes

| Class                                | Width                                                  | Input                       | Gets                                                                                                                           |
| ------------------------------------ | ------------------------------------------------------ | --------------------------- | ------------------------------------------------------------------------------------------------------------------------------ |
| Phone                                | 320–767 px (design floor 360; 320 is the reflow check) | Touch                       | Phone layouts, touch effects. iPad mini portrait (744 px) and 640 px Android tablets land here and get the sm two-column grids |
| Tablet portrait                      | 768–1023 px (md)                                       | Touch, sometimes a trackpad | Tablet layouts, touch effects (pointer effects per event if a trackpad is used)                                                |
| Tablet landscape / iPad Pro portrait | 1024 px and up                                         | Touch, sometimes a trackpad | **Desktop layouts with touch effects** (pointer effects per event if a trackpad is used)                                       |
| Desktop                              | 1024 px and up                                         | Mouse or trackpad           | Desktop layouts, pointer effects                                                                                               |
| Phone landscape                      | `(orientation: landscape) and (max-height: 500px)`     | Touch                       | Its own hero and menu variants                                                                                                 |

**Width decides layout; input decides effects.** Breakpoints place things. Hover and pointer capability decide which pointer effects run.

## 2. Core rules

**Input detection**

- CSS hover styling uses Tailwind's `hover:` variant, which already compiles to `@media (hover: hover)`, so taps never leave a stuck hover.
- The pointer-effects chunk (spotlight, tilt, magnetic, hero glow follow) loads only while `(any-hover: hover) and (any-pointer: fine)` matches, re-checked on change. Each handler also ignores `pointerType === "touch"`. Phones never load it; an iPad with a trackpad does.
- Lenis loads only when the _primary_ pointer is fine: `(pointer: fine) and (hover: hover)`, motion allowed, `syncTouch: false`. Phones and tablets keep native momentum scrolling.
- Never sniff the user agent or `ontouchstart` (iPadOS sends a Mac user agent; emulators report `ontouchstart` as false).
- No gyroscope or device-orientation effects: iOS shows a permission prompt.

**Every pointer effect has an animated touch version.** These are press feedback, in-view motion, scroll-linked motion or tap-to-act (§3). Nothing essential is hover-only, and every hover path also has a focus path.

**Where motion runs**

- CSS first: reveals, presses, ambient drifts, in-view demos and the hero entrance are CSS transitions and keyframes on `transform`/`opacity`. They keep running on the compositor while hydration blocks the main thread.
- Motion (`m` + `LazyMotion`, not `motion`) is only for springs, drag, sequenced centerpieces and the `useScroll` fallbacks where CSS scroll timelines are missing. The full `motion` component would take about 30% of Home's 150 KB budget.
- Above the fold, nothing waits for hydration or fonts. The hero is CSS from first paint, and no LCP candidate starts at opacity 0 (the photo starts at 0.01).
- The shared reveal IntersectionObserver runs from a tiny inline script (plain JS, under 1 KB), so reveals work before hydration. The hidden start state applies only under an `html.js` class that script sets. Elements first seen _above_ the viewport (back navigation, scroll restoration) reveal instantly.
- Pre-rendered layers move or fade. Never animate `background-position`, `box-shadow`, `filter`, `height` or a path's `d`. The one exception is `stroke-dashoffset`, on one path at a time.
- No static `will-change` in stylesheets; set it only while an interaction is active.

**Things that move on their own (WCAG 2.2.2, decided by Tanishq: per item)**

- Hero signal-line drift and hero glow drift stop within 5 s of first paint (the draw included). A tap, pointer move or the hero scrolling back into view restarts them.
- Looping videos and the VYRO gauge demo get a small Pause/Play icon button.
- Baby's first scenario plays once on entering view, in under 5 s. Micro-demos and the MyCounselHub flow play one pass and hold.
- All loops are time-based, so 30 fps Low Power Mode and 120 Hz screens behave the same. They pause off-screen and in hidden tabs (`usePauseWhenHidden`: IntersectionObserver + `visibilitychange`) and resume on `pageshow`.

**Reduced motion**

- CSS sets the final states before JS runs. JS only follows (`useReducedMotionSafe`).
- Allowed: opacity-only fades of 150 ms or less for the menu, palette, toast and page cross-fade, with no scale, slide or morph. The reading-progress bar keeps tracking scroll, because it shows position like a scrollbar.
- The header stays pinned and visible.
- Also honour `prefers-contrast: more` and `forced-colors: active` (no grain, grid or glows), and `prefers-reduced-transparency` (opaque header and overlays).

**Touch ergonomics**

- Standalone controls are at least 44×44 px on coarse pointers; buttons are 48 px, with gaps of 8 px or more. Inline text links are exempt. axe enforces the 24 px WCAG minimum.
- Every tappable element has press feedback through one shared token-driven `:active` style (`surface-2` fill or 0.7 opacity, `--duration-fast`). Tailwind's preflight removes the tap highlight, so without this taps give no feedback.
- Large scrolling surfaces (cards, bento tiles, proof rows) start their press effect about 100 ms after `pointerdown` and cancel on `pointercancel` or scroll, so a scroll that starts on them doesn't flash. Small controls press immediately.
- `touch-action: manipulation` on buttons, chips and toggles (no double-tap zoom on repeated taps). `touch-action: none` only on true drag handles. Charts use `pan-y`. Never block vertical page scrolling.
- Every drag has a single-tap alternative (WCAG 2.5.7) plus keys.
- `overscroll-behavior-x: contain` on every horizontal scroller (tables, steppers, chart scrub areas).
- Never disable pinch zoom. Form controls use 16 px text or more (no iOS zoom on focus).

**Viewport and safe areas**

- `viewport-fit=cover` via Next's `viewport` export. Gutters, the footer, dialogs and any fixed bottom UI use `env(safe-area-inset-*)`.
- In-flow full-height sections use `svh`, capped in `rem` for tall iPad Pro screens. Only fixed overlays use `dvh`. Never `100vh`.
- `<html data-scroll-behavior="smooth">` keeps Next 16 from smooth-scrolling on route changes. `scroll-behavior: smooth` applies only under `prefers-reduced-motion: no-preference`. `scroll-padding-top` equals the header height (WCAG 2.4.11). Lenis loads `lenis.css`.
- The page never scrolls sideways from 320 to 1920 px. Only labelled, focusable regions (tables) scroll horizontally. Never put `overflow-x: hidden` on `html` or `body`.
- DOM order = visual order = focus order at every width (no CSS `order` or `dense` reordering).
- Update `<meta name="theme-color">` on theme change (Android toolbar tint). Set the `bg` token on `html` as well as `body` (iOS 26 tints from the page background).

**Honesty labels follow their content.** "Simulated values…", "Scripted demo…" and "Illustrative screens." sit next to the element they describe at every width, outside any swipe track, and must be visible at 360 px.

**Overlays.** Native `<dialog>` and `popover` enter with `@starting-style`. Safari and Firefox don't support `overlay` exit transitions, so exits add a closing class, wait for `animationend` (150 ms opacity), then call `close()` / `hidePopover()`. Under reduced motion, close immediately.

**Print.** `@media print` forces final states: revealed content, final count-up values, drawn signal lines.

## 7. Performance and compatibility (checked 20 Oct 2026)

- **Budgets.** Lighthouse mobile scores the touch path, so touch effects add no library code to Home's initial JS: CSS plus one small delegated `pointerdown`/`pointerup` listener (touch-point bloom, glow tap) with no Motion. The pointer chunk never loads on phones. CI fails if Home first-load JS exceeds 150 KB.
- **CSS scroll-driven animations** (`animation-timeline`): Chrome/Edge 115+, Safari/iOS 26+, Firefox only from 161 (treat stable Firefox as unsupported). Use them inside `@supports`. Scroll effects that carry information (progress bar, About timeline, MLOps chart) fall back to Motion `useScroll`; decorative ones stay static.
- **Same-document View Transitions via React `<ViewTransition>`:** Chromium 125+ (it uses transition types and `view-transition-class`), Safari 18+, Firefox 144+. Unsupported browsers swap instantly.
- **`overlay` exit transitions:** unsupported in Safari and Firefox, so use the JS close step (§2 Overlays).
- **`popover` light dismiss:** Safari 17+, Chrome 114+, Firefox 125+.
- **`field-sizing`:** Chrome 123+, Safari 26.2+, Firefox 152+; older browsers keep fixed rows.
- **`Intl.Segmenter`:** Baseline (Chrome 87, Safari 14.1, Firefox 125). Devanagari uses system fonts (Latin subset), so reserve its line height.
- **iOS Low Power Mode:** rAF drops to 30 fps (time-based loops fix it) and muted autoplay is refused (poster + play button).
- **iOS `:active`** needs a touchstart listener in the tree; React's root registers one. Verify on a device.
- **`dvh`** janks while the iOS address bar collapses (WebKit bug 266835), hence `svh` in flow.
- **`backdrop-filter`** scroll jank on Firefox for Android (Mozilla bug 1732817): keep it to the small header bar.
- **Film grain:** rasterize the SVG noise at build time into a small tile on `body`. No runtime `feTurbulence`, no fixed full-screen overlay.
- **Images:** add 640 and 960 px screenshot variants (never upscaled) for bento posters and phone figures. Every image gets an accurate `sizes`. A 3x phone picks the 1280 px photo variant, so keep that AVIF near 200 KB.
- **INP:** tap handlers do the minimum. Filter, chip and seed changes run inside `startTransition`; d3 scales are memoised; drag positions use Motion values, not React state per `pointermove`.
